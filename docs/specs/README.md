# 规格文档 · specs/

**只给大改动**。一个规格 = 一个目录，目录里三件套：

```
docs/specs/0001-<slug>/
  requirements.md   要什么（用户故事 + 可测验收）
  design.md         怎么做（方案、涉及文件、数据结构变化）
  tasks.md          做几步（可勾选的任务清单）
```

## 什么时候要开规格

满足任意一条就开，否则只记 `backlog.md` 一行：

- 触及超过 3 个文件
- 改数据模型或字段（`data/schema/*`）
- 改用户可见的交互行为
- 新增运行时依赖
- 跨阶段（例如同一次改动同时动 P1 与 P3）

这条阈值抄在 [AGENTS.md](../AGENTS.md) 里，不靠临场判断。

## 命名

`NNNN-slug`，`NNNN` 从 `0001` 起顺序递增（不复用），`slug` 用小写英文与连字符。
例：`0001-p1-tang-dynasty/`、`0002-certainty-encoding/`。

## 三件套的模板

`requirements.md`

```markdown
# 需求 · <标题>

## 背景
为什么现在做（引用 backlog ID）。

## 用户故事
作为读者 / 贡献者，我希望……以便……

## 验收标准（可测）
- [ ] 具体到能一条条打勾，不写「体验更好」这类空话
```

`design.md`

```markdown
# 方案 · <标题>

## 现状
现在是怎么运作的，卡在哪。

## 方案
数据流怎么变、新增/修改哪些函数。

## 涉及文件
- src/xxx.ts（改什么）

## 数据结构变化
有 schema / 类型变更就写，没有就写「无」。
```

`tasks.md`

```markdown
# 任务 · <标题>

- [ ] 第 1 步（对应文件）
- [ ] 第 2 步
- [ ] 跑 npm run check
- [ ] 更新 backlog 状态与 progress
```

## 收尾

三件套全部勾完之后：

1. 把 `backlog.md` 中对应行状态改为「完成」
2. 更新 `progress.md` 的焦点与「最近完成」
3. 规格目录**保留不删**——它是这个改动为什么这样做的唯一记录
