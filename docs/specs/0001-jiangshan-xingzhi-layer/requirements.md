# 需求 · 江山时序「诗歌层」

## 背景

以 [jiangshan-map](https://github.com/DeanChensj/jiangshan-map)（GPL-3.0，原生 JS）为**基线**做改造，不向上游提 PR。
对应看板 `R-2`（诗歌层）与 `R-3`（作品数据补齐）。

## 问题

他的行迹卡片里，每一站都有一句引文（`quoteZh`），例如：

> 苏轼《定风波》：「竹杖芒鞋轻胜马，谁怕？一蓑烟雨任平生。」

这是**摘句**，不是**诗**。读者读完这一句就没有下文了：没有全文、没有分阕、没有注释、没有写作背景、没有系年可信度。

## 用户故事

作为读者，我在人物行迹里读到一句喜欢的诗，我希望**直接点开读完整首**，并且知道它写于哪一年、在哪里、有哪些典故——以便我不是在读一条摘录，而是在读一首诗。

## 验收标准（可测）

- [ ] 苏轼行迹页：11 条引文中 ≥6 条变成可点链接
- [ ] 李白行迹页：12 条引文中 ≥5 条变成可点链接
- [ ] 诸葛亮行迹页：11 条引文中 ≥10 条变成可点链接
- [ ] 张骞行迹页：9 条引文中 ≥9 条变成可点链接
- [ ] 点开链接后显示：标题、作者·年份·地点、正文、**大意**、**赏析**、写作背景、注释、出处、系年标记
- [ ] **版式统一横排居中**，按句读断行（不在句中硬断）
- [ ] **赏析只收自撰**：每条必带 `by: 本站自撰` 与 `license`，不得引用点校本
- [ ] 控制台零报错；`index.html` 之外不改基线主逻辑
- [ ] 覆盖率可用脚本复现（`scripts/_gap_report.cjs` 输出 `coverage` 字段）
- [ ] **作品可检索**：搜索框输入作品名 / 副题片段 / 作者名，能出现「作品」类结果，点击直开阅读器

## 作品检索的边界

- 索引 `titleZh`、`titleEn`、`alias`、作者名（经 `modernZh`）；
- **不索引正文**（成本高、命中噪音大，列为 `R-6` 待议）；
- 与既有地名/事件重名时，可能被基线自身的排序挤到后面——属继承行为，不在本层修。

## 收录边界

**诗词赋史全覆盖**（2026-10-31 确认）。全部横排，区别只在标记：

| 文体 | `genre` | 标记 |
|---|---|---|
| 诗 / 词 / 赋 | `shi` / `ci` / `fu` | — |
| 文（表、书、记） | `wen` | 摘录 |
| 史传（纪、传、志、年谱） | `history` | 摘录 |

史传只收**被引用的段落**，不复刻全书——引文一律取自基线数据里的原句，避免转写错误。

## 内容准确性要求

- **大意**：写「这一首在说什么、怎么转、落在哪」，不做逐句对译；不加原文没有的信息。
- **注释**：解释用法、语境与典故出处，不能只给同义词（反例：「芒鞋：草鞋」）。每条宜 1–3 句。
- 赏析正文只做「文本内部能支撑的判断」：结构、用字、语气、典故用法。
- **允许结合史事推演，但必须放进 `appreciation.inference`**：
  - 界面上以朱砂虚线 + 「推测」标签标出，与正文判断视觉分离；
  - 尽量给出 `basis`（依据），且依据必须落在该条目的 `background` 或 `source` 里；
  - **没有依据的推断不收**，宁可只写文本内的判断。
- 拿不准的篇目宁可暂缺，不收。

## 非目标（本批不做）

- 不新增行迹（人物 / 站点）——那是 `R-4`
- 不做英文全文与繁中全文，只保证标题双语
- 不做移动端专用布局
- 不做史传全本录入
