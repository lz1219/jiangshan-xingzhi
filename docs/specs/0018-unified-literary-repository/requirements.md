# 需求 · 统一文献库与作品典籍整合 (R-17 / Spec 0018)

## 一、背景与问题

1. **入口与实体割裂**：目前文献站将“精选作品（69篇）”与“典籍/语料库（8.8万首/2300卷）”分为两个互不通气的模式。一篇作品没有全局统一身份，同一作品在精选读本、宋词语料和人物行迹中是彼此割裂的孤立数据。
2. **两套正文与重复修补**：历史体系中在本地 JSON 和语料库维护两套正文，修补成本高且容易漂移。用户明确要求：以线上 PostgreSQL 数据库为唯一依据，不再维护本地 SQLite，不再逐条同步修补重复正文。
3. **见证与摘录缺乏统一结构**：杜甫《寄李十二白二十韵》（长诗截取四句）、苏轼《卜算子》（结尾“寂寞沙洲冷” vs “枫落吴江冷”异文）等缺少清晰的文本见证契约。

## 二、核心需求目标

1. **单一文献入口**：
   - 读者使用一个文献入口，按作品、人物、典籍目录等多种方式平滑浏览；
   - 精选篇目默认呈现完整研读（忠实译文、定位词注、自撰赏析、时空行迹）；非精选语料篇目呈现可靠底本与来源，并可渐进补齐研读。
2. **统一作品身份（Canonical Work）与多版本见证（Witness）**：
   - 作品拥有全局唯一稳定标识（`work_key`），统一题名、别名、体裁、作者与系年；
   - 正文真相归于版本见证：每个作品挂载 1 个主见证与 0~N 个对比见证，明确标出摘录范围与版本异文；
   - 见证可关联至 `jiangshan` 语料库物理实体（`corpus_poem` 或 `text_unit/paragraph`），附带上游提交、URL、JSON 指针及 SHA-256。
3. **行迹关联解耦**：
   - 行迹站点引用是作品的外部时空关系（`stop-quotes-work` / `composed_at` / `mentioned`），与作品身份解耦，杜绝为入库虚构站点，也允许无站点引用的名篇独立存在。
4. **学术与 AI 伦理合规**：
   - 译文忠实通顺、注释可定位、赏析本站自撰；AI 起草内容必须显著标注生成来源与未审校状态，严禁冒充古籍或定论。
5. **技术底线**：
   - 零构建、无 npm 运行时依赖；严格执行发布纪律与写前备份。
