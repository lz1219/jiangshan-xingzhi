## 1. 定位与非目标

**一句话**：在 [江山时序](https://github.com/DeanChensj/jiangshan-map) 的行迹上，把一句摘引展开成一条可读的文献。

**名**：江山行止。**行**为位移（行迹路线），**止**为驻足（常驻地、贬所、写诗的地方）。拖动是行，点开是止。

**与上游的关系**：本仓库是上游的改造分支，**不向上游提 PR**。上游提供地图、疆域、行迹与引文；我们只加「笺注层」。

**非目标**：

- 不改上游的地图渲染、疆域快照、地名沿革、人物行迹数据。
- 不做后端、不做账号、不做云端存储。
- 不引入打包器与运行时依赖（零依赖是上游的卖点）。
- 不收录有版权的点校本注释与赏析。
- 不追求「全史」式覆盖：先让被引用的 74 处都有得读，再谈扩充。

## 2. 领域词汇表

术语以此为准，代码、文档、提交信息都用这套词。

| 词 | 含义 | 容易误解成 |
|---|---|---|
| **行 journey** | 一位人物的完整行迹，上游 `HISTORICAL_JOURNEYS` 的一条，共 7 条 | 不是「诗」；也不是我们的数据结构 |
| **止 stop** | 行迹中的一站：年份 + 坐标 + 古今地名 + 叙述 + 一句引文 | 不是「景点」；短途之游也占一站 |
| **引文 quote** | 站上的 `quoteZh`，形如 `苏轼《定风波》：「竹杖芒鞋…」` | 不是全文，是**摘句** |
| **作品 work** | 我们数据层的一条：正文、大意、注释、背景、赏析、系年、出处 | 与引文按书名关联，不是复制品 |
| **笺** | 点开引文后的阅读层：把摘句展开为作品 | 不是「赏析」，赏析只是其中一块 |
| **文体 genre** | `shi` 诗 · `ci` 词 · `fu` 赋 · `wen` 文 · `history` 史传 | 与「朝代」无关 |
| **摘录** | 文与史传只收被引用的段落，界面上必须标出 | 不是全本，也不是残缺 |
| **推测 inference** | 赏析中结合史事的推演，须给 `basis` | 与正文判断分开呈现，不得混写 |

## 3. 不可逆决策

**这是唯一清单。** README 与 AGENTS 的说法都是它的投影，冲突时以本节为准。

| # | 决定 | 理由 | 代价 |
|---|---|---|---|
| 1 | **以上游为基线改造，不向上游提 PR** | 上游 GPL-3.0 + 原生 JS + 单页；我们要改的正是交互与数据层，PR 形态只会变成「重写」 | 整个分支继承 GPL-3.0，不能闭源 |
| 2 | **只加不改：扩展点走 `__ATLAS_MIXINS`** | `app.js` 15k 行、无模块系统；改主逻辑的维护成本远超收益 | 受限于既有 DOM 与事件，样式要迁就 |
| 3 | **原文逐字取自基线，不手抄** | 手抄《史记》必然出错；引文已是现成的权威文本 | 只能读「被引用的段落」，不能给全本 |
| 4 | **诗词赋史全覆盖，文与史传标「摘录」** | 读者有权知道给的是全文还是节选 | 界面多一个标签，数据多一个约定 |
| 5 | **赏析只收自撰，推测单独成块并给依据** | 点校本有版权；混写会把推断伪装成定论 | 写作成本高，每条都要写 `basis` |
| 6 | **一切叙述必须有据，且写出处** | 读者凭这个项目读史；一句无据的因果就是造假。**不写史料未载的年龄、时长、因果、评价** | 写作变慢，每条都要能指到卷次；拿不准的部分只能不写 |
| 7 | **新增人物走 overlay，不改上游数据文件** | 上游 `lore_data.js` 是它的数据；我们另建 `atlas_overlay.js` 在运行时推入，才不会被 `git fetch upstream` 冲掉 | 多一层加载顺序依赖（必须在 `app.js` 之前） |

## 8. 与文献站（poem-data）的互链

两个站点分工：

| 站点 | 回答的问题 | 数据 |
|---|---|---|
| **江山行止**（本仓库） | **在哪** | 疆域、行迹、站点、地图 |
| **文献**（poem-data） | **怎么读** | 作品注疏、人物仕历、66,968 首诗、1,301 卷原典 |

**互不给对方画界面**：地图只在江山行止，注疏只在文献站，用深链跳转。

### 链接地址可配置

`js/atlas_links.js` 是唯一配置点：

```js
window.ATLAS_CORPUS_BASE   // 外层页面可预设；默认按环境推断
```

- 本地：`http://127.0.0.1:5322/`
- 线上：`https://lz1219.github.io/poem-data/`

两个站点换部署地时，只改这一处（或在页面里预设变量），**不需要动渲染代码**。

### 三处入口

| 位置 | 链接 |
|---|---|
| 阅读器底部 | 在文献站读全篇 ↗ |
| 人物面板导语下 | 在文献站查此人 ↗ |
| 文献站侧 | 行迹站点「地图 ↗」、人物「在地图上看 ↗」、作品徽标行「地图 ↗」 |

### 一个坑

`ATLAS_WORKS` 的条目里**没有 key 字段**（key 是对象的键名）。互链需要 key，
所以 `findPoem()` 命中时会把键名补到 `poem.__key` 上，不污染原数据。
